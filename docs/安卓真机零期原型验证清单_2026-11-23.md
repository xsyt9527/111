## 三、三项必填结论

### 1. 触屏跟手性

- 观察：摇杆按下到鱼转向/移动的延迟；松手是否立刻减速；斜向拖动是否顺滑。
- 判定标准：
  - 通过 = 手指移动与鱼移动方向一致，延迟可接受（约 1 帧内），松手不漂移。
  - 不通过 = 明显滞后 / 方向反了 / 松手仍在游 / 斜向抖动。
- **结论**：______（通过 / 不通过）
- **具体现象**：______

### 2. 自动锁定可预期性

- 观察：按下攻击时，鱼是否咬向玩家"看起来最近/最该咬"的那条；有没有咬到身后或隔着障碍的鱼。
- 判定标准：
  - 通过 = 目标与玩家视觉预期一致，连点时不会频繁换目标。
  - 不通过 = 咬到明显更远的目标 / 反复横跳 / 想咬小鱼却咬到大鱼。
- **结论**：______（通过 / 不通过）
- **具体现象**：______

### 3. 掉体型可读性

- 观察：被咬后鱼身缩小是否一眼可见；血条/体型条变化是否同步；濒死爆发（体型≤15%）的暗红边缘脉冲是否注意到。
- 判定标准：
  - 通过 = 一次咬就能看出"变小了"，濒死窗口有明确提示且知道"只能用一次"。
  - 不通过 = 看不出掉血 / HUD 与鱼身不同步 / 暗红脉冲太弱或太吵。
- **结论**：______（通过 / 不通过）
