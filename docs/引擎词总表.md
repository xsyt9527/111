# 深海食纪 — 引擎词总表

> 沿用金币项目惯例：按文件分类收录本项目用到的引擎词（API/概念/节点），
> 每课新增时更新。**写得出 = 真学会了。**

## 项目级配置（project.godot）

| 引擎词 | 所属 | 释义 |
|---|---|---|
| `config/features` | application | 引擎特性标记（4.7 / Mobile 渲染），锁定引擎识别 |
| `window/stretch/mode="canvas_items"` | display | 窗口缩放模式：按画布元素缩放，适配不同分辨率 |
| `window/stretch/aspect="keep"` | display | 保持宽高比（横屏 16:9） |
| `emulate_touch_from_mouse` | input_devices | 鼠标模拟触摸：开发期 PC 上也能收到触摸事件 |

## 第 1 课 · 玩家鱼游动（按文件分类）

### scripts/yu.gd（玩家鱼蓝图）

| 引擎词 | 释义 |
|---|---|
| `extends Node2D` | 继承 Node2D：有位置/旋转/缩放的 2D 节点 |
| `class_name Yu` | 注册全局类名，别的脚本可把类型写成 `Yu` 而不是 `Node2D` |
| `@export var yidong_sudu := 300.0` | 导出变量：出现在检查器里可直接调，`:=` 为类型推断 |
| `var mubiao_dian: Vector2` | 普通成员变量，不导出；由 Main 写入的游动目标点 |
| `_ready()` | 节点进入场景树后调用一次（捡金币第 1 课亲戚） |

### scripts/main.gd（主场景协调者）

| 引擎词 | 释义 |
|---|---|
| `_unhandled_input(event)` | 未被 UI/其他节点消费的输入事件会送到这里（事件驱动，不代表每帧调用） |
| `InputEventScreenTouch` | 触摸按下/松开事件；`event.pressed` 区分按下（true）与松开（false） |
| `InputEventScreenDrag` | 触摸按住期间的移动事件（**没有** InputEventScreenMotion 这个类型——引擎会解析报错） |
| `event.position` | 事件的屏幕坐标（本场景无相机，等于世界坐标） |
| `@onready var yu: Yu = $Yu` | 场景树就绪时取子节点引用，带类型标注 |

### scenes/（场景与主场景）

| 引擎词 | 释义 |
|---|---|
| `run/main_scene` | project.godot 里的运行入口场景；F5 与导出的 APK 都从这里启动 |
| `instance=ExtResource(...)` | .tscn 中把另一个场景实例化后挂进本场景（场景内静态实例化） |
| `scale = Vector2(20, 11.25)` | 精灵缩放：64×64 海床贴图放大到 1280×720 铺满 |

## 第 2 课 · 鱼群生成（按文件分类）

### scripts/yu_npc.gd（NPC 鱼蓝图）

| 引擎词 | 释义 |
|---|---|
| `class_name YuNpc` | 注册全局类名，生成器里可写 `var xin_yu: YuNpc` |
| `@export var tie_tu_shu_zu: Array[Texture2D]` | 类型化数组导出：检查器里可拖入多张贴图，限制元素类型 |
| `randf_range(a, b)` | 返回 [a, b] 之间的随机小数；Godot 4 启动自动播种，无需 randomize() |
| `pick_random()` | Array 方法：随机返回一个元素 |
| `Vector2.ONE` | 常量 (1, 1)；`Vector2.ONE * tixing` 表示等比缩放 |
| `get_viewport_rect().size` | 当前视口（屏幕）尺寸；比写死 1280×720 更稳 |
| `queue_free()` | 请求在当前帧末尾释放节点（从场景树移除并回收内存） |
| `scale` / `$Sprite2D.flip_h` | 节点缩放；精灵水平翻转，让鱼头朝前进方向 |

### scripts/yu_qun.gd（鱼群生成器）

| 引擎词 | 释义 |
|---|---|
| `preload("res://...")` | 编译期加载场景资源，得到 PackedScene |
| `YU_NPC_CHANGJING.instantiate()` | 由 PackedScene 创建一份运行时实例（还没进树） |
| `add_child(xin_yu)` | 把实例挂成当前节点子节点；此时才触发它的 `_ready()` |
| `Timer`（节点） | 定时器节点：到点发出 `timeout` 信号 |
| `$Dingshi.timeout.connect(callable)` | 代码连接信号：到点调用指定方法 |
| `wait_time` | Timer 等待时长（秒） |
| `one_shot = true` | 只响一次；每次需要手动 `start()` 重新计时 |
| `start()` | 启动/重启计时器 |
| `get_children()` | 返回全部直接子节点；配合 `is YuNpc` 精确计数 |
| `is`（类型判断） | `zi is YuNpc` 判断节点是否为该类实例 |

### scenes/（场景与装配）

| 引擎词 | 释义 |
|---|---|
| `[node name="Dingshi" type="Timer" parent="YuQun"]` | .tscn 中声明 Timer 子节点及其属性 |
| `one_shot = true`（场景文件） | 场景保存的 Timer 属性，与检查器一致 |
| `ext_resource type="Script"` | 场景引用外部脚本资源 |

### 概念小结

| 概念 | 一句话 |
|---|---|
| 随机间隔生成 | 每次超时后用 `randf_range` 重设 `wait_time`，鱼群密度有起伏 |
| 生成器 / 蓝图分工 | 生成器管何时、从哪、多快；NPC 管长相、移动与自我回收 |
| 屏幕外回收 | 动态节点用 `queue_free()` 释放，否则节点越积越多 |

## 第 3 课 · 大吃小判定（按文件分类）

### scripts/yu.gd（判定与受伤）

| 引擎词 | 释义 |
|---|---|
| `Area2D` | 不可见的物理检测区：别的区域进入时发信号；只检测不推挤 |
| `collision_layer` | 「我是什么」——我挂的牌子，别人按层找到我（1=玩家，2=鱼群） |
| `collision_mask` | 「我监视谁」——勾了谁的层，谁进我的圈我就发信号 |
| `area_entered(area: Area2D)` | Area2D 的检测信号：参数就是闯进来的那个 Area2D |
| `qu.get_parent() as YuNpc` | 取检测区的宿主节点；`as` 类型转换，转不成得 null |
| `modulate` | 节点颜色调制（乘在贴图上）：受伤闪红、恢复都用它 |
| `Color(1.0, 0.4, 0.4)` / `Color.WHITE` | RGB 颜色值；WHITE 常量 = 原色 |

### scenes/（检测区装配）

| 引擎词 | 释义 |
|---|---|
| `CollisionShape2D` | 给 Area2D 定形状与大小的子节点，无形状会警告 |
| `sub_resource type="CircleShape2D"` | .tscn 内嵌形状资源；`radius = 22.0` 是圆半径 |
| 判定圈随 scale 缩放 | NPC 根节点 `scale = tixing`，子节点 CollisionShape2D 自动跟着变大变小（白送） |
| `WudiDingshi (Timer, one_shot)` | 无敌计时器：复用第 2 课 Timer 模式做受伤保护 |
| 多形状合并成一个区 | 一个 Area2D 可挂多个 CollisionShape2D，但形状**合并**为一个检测区、一个信号，分不清触发来源 |
| 分行为须分 Area2D | 想"两个范围、两种反应"（如吃区大/伤区小）要两个 Area2D 各配形状、各连信号——第 7 课磁吸 buff 的骨架 |

### 概念小结

| 概念 | 一句话 |
|---|---|
| 单向检测防重复 | 只有玩家 mask=2 在监视，NPC mask=0 沉默——一次碰撞只发一次信号 |
| 大吃小规则 | `tixing > tixing` 严格大于才吃得下；相等算撞大鱼 |
| 无敌帧 | 受伤后 1 秒不重复受伤（Timer + wudi 标记），期间仍能吃小鱼 |
| 挂钩点思维 | `bei_chi()` / `_shoushang()` 先挖好入口，第 5/8 课直接在入口记账 |

## 第 4 课 · 数据驱动鱼种（按文件分类）

### scripts/yu_zhong.gd（鱼种模具）

| 引擎词 | 释义 |
|---|---|
| `extends Resource` | 继承资源类：纯数据容器，不是场景节点、不进场景树 |
| `class_name YuZhong` | 注册全局类名后，.tres 与类型化数组才能引用它 |
| `@export var tie_tu: Texture2D` | Resource 也能 @export：字段出现在检查器里可直接填 |
| `resource_path` | Resource 的 `res://` 路径（探针里用来核对抽中哪种鱼） |

### data/yuzhong/*.tres（鱼种数据）

| 引擎词 | 释义 |
|---|---|
| `.tres` 资源文件 | 填好数据的 Resource 实例存成磁盘文件；双击检查器可编辑 |
| `script_class="YuZhong"` | .tres 头部标记：这份数据用哪个模具解析 |
| `[ext_resource type="Script" uid=...]` | .tres 引用模具脚本与贴图；uid 是资源的稳定身份证 |
| `load_steps` | 资源头部记录的加载步骤数（编辑器自动维护） |

### scripts/yu_qun.gd（注册表）

| 引擎词 | 释义 |
|---|---|
| `Array[YuZhong]` | 类型化资源数组：检查器拖入 .tres，元素类型受限 |
| `pick_random()`（资源数组） | 注册表抽取：随机返回一个鱼种数据 |
| Create New → Resource… | 编辑器新建资源入口：选模具 → 检查器填数 → 存成 .tres |

### 概念小结

| 概念 | 一句话 |
|---|---|
| Resource 三分工 | 脚本=模具（定结构）、.tres=数据（存数值）、检查器=填表（改数值） |
| 注册表模式 | 加新鱼零代码：新建 .tres 填字段 + 拖进数组（第 6 课强化卡复用此套路） |
| 资源注入顺序 | 生成器 add_child 前赋 yu_zhong，_ready 消费——数据先于生命周期 |
| 数据与代码分离 | 数值全在数据文件里改，代码只认结构——策划改表不动程序员代码 |

### project.godot（Autoload 注册）

| 引擎词 | 释义 |
|---|---|
| `[autoload]` 段 | 项目设置里的全局单例注册表：名字 = 脚本路径 |

|---|---|

### scenes/Main.tscn + jing_yan_ui.gd（经验条 UI）

| 引擎词 | 释义 |
|---|---|
| `CanvasLayer` | 独立画布层：树上是孩子（随场景生灭）、画布上独立（不继承 Node2D 变换，钉死屏幕） |
| `ProgressBar` | 进度条控件：max_value/value 两值驱动，适合经验/血量 |
| `offset_left/top/right/bottom` | Control 控件的矩形四边（锚点为 0 时即屏幕像素坐标） |
| `Label` | 文本控件；`"Lv.%d" % deng_ji` 是格式化字符串写法 |
| `@onready var x = $子节点` | _ready 时才取节点引用（UI 脚本标准开头） |

### 概念小结

| 概念 | 一句话 |
|---|---|
| 账本模式 | 唯一所有者（数值只有账本能写）+ 唯一入口 + 信号广播——账本不认识任何场景节点 |
| 本级经验制 | 升级扣除已用阈值从零重攒（jing_yan -= yuzhi），不是累计总分 |
| 生命周期 vs 渲染 | 挂在哪=跟谁生灭（Autoload 跨场景/UI 随场景）；怎么画=坐标继承谁（CanvasLayer 切断继承） |
| 信号解耦 | 广播方不知道谁在听——第 6 课弹窗只需自己 connect，账本零改动 |

| 引擎词 | 释义 |
|---|---|
| 场景实例化（instance=ExtResource） | 独立场景嵌进 Main：可单独编辑、自带注册表、可复用 |
| `PanelContainer` | 带背景板的自适应容器（卡牌底板） |

| `custom_minimum_size` | 控件最小尺寸：容器布局据此分配空间 |
| `theme_override_font_sizes/font_size` | 单节点字号覆盖（不建主题时的快速调法） |

### 概念小结

| 概念 | 一句话 |
|---|---|
| 引擎级暂停 vs 手动停系统 | 一行 paused 冻结全场 vs 每加一个系统补一处 stop——新系统自动继承冻结 |
| 不放回抽样 | duplicate→shuffle→slice 三连：原表不动、随机、无重复 |
| 常量数据化 | 常量退役换 .tres，等值切换零行为变化；改表调参零代码 |
| 接口预埋 | 信号先 emit 无消费者（ka_yi_xuan）——下家一行 connect 即接入 |
| 预期中间态 | 分步实现里"点了没反应"可能是下一step还没写——区分它和 bug 是工程判断力 |

| `set_ease(Tween.EASE_OUT)` | 缓动曲线：开头快结尾缓——"噌一下再放缓"最自然 |
| 链式两段 tween | 同一 tween 连写两个 tween_property：前段播完自动接后段（弹大→回弹） |
| `sin(时间 * 10.0)` | 正弦周期函数 -1~+1 循环：程序化摆尾的发动机（零关键帧） |
| `rotation`（Sprite2D） | 子节点自转：摆尾只转贴图不动逻辑 |

### scenes/Yu.tscn（双 Area2D 结构）

| 引擎词 | 释义 |
|---|---|
| 节点改名（PandingQu→ShangQu） | 行为零改动只换名字：职责说清楚（伤=Shang 上的"伤"） |
| 双 Area2D 分职 | ChiQu 大圈只打吸附标记（r=90）/ ShangQu 小圈管吃伤判定（r=22）——同 Area2D 多形状会合并成一个区，分不了行为 |
| 形状 scale 乘法 | `CollisionShape2D.scale *= ...` 只放大这一个圈：磁吸卡不碰判定圈 |

### scripts/yu_npc.gd / zhang_ben.gd

| 引擎词 | 释义 |
|---|---|
| `var bei_xi: Yu = null` | 吸附标记：非空=被吸中，NPC 自己朝它游（NPC 自决） |
| `move_toward(目标, 步长)` | 朝任意点匀速移动：被吸追踪与玩家移动同一把尺子 |
| `int(值 * 倍率)` | 乘完截断成整数：倍率入账本后在记账侧乘算 |

### 概念小结

| 概念 | 一句话 |
|---|---|
| 显示与状态分离 | tixing 数值即时到位（判定不等动画），Tween 只伺候眼睛 |
| 分行为须分 Area2D | 吸附要早触发（大圈）、判定要准触发（小圈）——两个半径需求天生不同 |
| 效果分发模式 | .tres 存键和值 + match 按键路由 + push_warning 兜底——加卡=数据+分支两处 |
| 预埋信号消费闭环 | 第 6 课 emit 无消费者 → 本课一行 connect 即活：接口先行完整走通 |
| 程序化动画 | sin 周期 + 相位时钟：数学就是动画师，不用画关键帧 |

| `ext_resource type="Texture2D"` | `.tres` 引用外部贴图：换皮=改 `uid`/`path`，`dengji`/`fenzhi`/速度/体型全部不动 |
| `uid://...` | 资源稳定标识：文件改名/移动后仍能找回；比手写路径抗重构 |
| `Texture2D` | 贴图抽象类型；`.tres` 只认这个类型，不关心底层是 PNG 还是压缩纹理 |
| `CompressedTexture2D` | PNG 经 Godot 导入后的运行时纹理类型；游戏里 `load()` 拿到的就是它 |
| `.import` 文件 | 导入配置+缓存索引：记录源文件、导入参数、生成的 `.ctex`；由编辑器维护，不手改 |
| `.gdignore` | 目录里放一个空文件，Godot 扫描时整目录跳过；`图片/` 原始素材因此不进导入、不进 APK |
| 导入即转换 | 源 PNG 不是直接打包：编辑器先按导入设置转成引擎纹理，再参与场景加载 |
| 尺寸归一化（管线约定） | 所有鱼先按 alpha 包围盒裁剪，再统一缩到高 40px；引擎里不再为每张图写缩放特例 |

### 概念小结

| 概念 | 一句话 |
|---|---|
| 素材归一化 | 裁剪透明边 → 统一高度 → 必要时镜像，三步在进引擎前做完；引擎里只认「默认朝右、40px 高」 |
| 朝向约定 | 所有鱼贴图默认朝右，`flip_h` 只负责左右；源图朝左的在导入前镜像，运行时不写特例 |
| 序列帧/图集 | 一张横条 = 四帧；`AtlasTexture` 按 `region` 抠帧，`SpriteFrames` 管播放，不切四张 PNG |
| 分层 | 背景 -10、装饰 -1、鱼 0：层次用数据表达，装饰永远在鱼后面，不挡玩法 |
| 换皮不改逻辑 | 鱼种表只换 `tie_tu` 引用；等级/分值/游速/体型范围原样保留——美术与玩法解耦 |
| 视觉与碰撞分离 | `flip_h`、`rotation` 只动画面；`Area2D` 判定圈是独立节点，换动画节点不会顺带改手感 |
| 素材目录隔离 | 原始 58MB 素材留在 `图片/`，加 `.gdignore` 后不参与导入和导出；正式产物只留处理后的 `assets/sucai/` |

### 概念小结

| 概念 | 一句话 |
|---|---|
| 能力是数据不是类 | 加能力 = 加一个 `.tres` + 拖进能力池；`match` 只负责效果实现，不负责数值 |
| 一份定义两处消费 | 玩家/NPC 读同一 Resource，差异只走 `npc_shu_zhi`/`npc_jian_ge` 两个覆写字段 |
| 唯一主动槽 + 被动叠层 | 主动覆盖、被动累加：两个容器，两种语义，不要混成一个数组 |
| 消化完成才记账 | 「吃了」不等于「拿到」：消化中死亡白吞；食谱计数必须和入账顺序绑定 |
| 平局保留先到者 | 最常吃只在不严格大于时不动：结果稳定、可解释，测试可复现 |
| 注入 RNG = 可复现 | 三选一不碰全局随机；固定种子就能断言「这次必出毒棘」 |
| 暂停弹窗三件套 | `paused` + `process_mode=WHEN_PAUSED` + `layer=100`：冻结全场、唯我独醒、盖住 UI |
| 0 候选必须解冻 | 空池/连续升级/全部被排除都可能走到 0：任何分支都要把 `paused` 放回去 |
| 切主动清瞬时状态 | 否则极速倍率、冲撞去重表、潜伏 alpha 会跨能力残留；冷却归零是「新技能可用」 |
| 潜伏只改索敌 | 隐身是感知层，不是无敌：碰撞/咬击照常，破隐三时机（咬中/受伤/到期） |
| 鸭子类型靠默认参数 | `shou_dao_yao_ji` 单参调用不破；新参数必须有默认值，契约靠 `has_method` |
| 先验活再做类型判断 | `is_instance_valid()` 必须早于 `is Yu`/属性读取：freed instance 是运行期错误，单测不一定覆盖 |
| 旧卡退役要删五层 | 脚本、场景、数据、账本、测试断言一起删；只删脚本会留下坏引用和假绿 |

## 插课 · 音效与音乐接入（2026-10-31，程序合成 + 播放器池 + 退出收尾）

> 12 条音效 + 1 首深海 BGM 全部用 Python + numpy **程序合成**（22050Hz 16bit 单声道 WAV，免版税自制），经 `YinXiang` Autoload 统一播发：11 条音效查表 → 6 个池播放器并发；BGM 单独常驻，`finished` 信号手动续播实现无缝循环。接入后八步门禁从 553 → 569 断言。
> 本课最大的坑不在播放、在**退出**：headless 测试进程退出时仍在播的音频流会被记成 `ERROR: N resources still in use`，门禁的 ERROR 筛查直接打红——由此挖出 Godod 退出序列的真相（资源检查早于场景树析构）与一串测试时序的坑。

| 引擎词 / 做法 | 释义 |
|---|---|
| `AudioStreamPlayer` 播放器池 | 6 个播放器常驻 `_chi` 数组：`fang()` 先找 `not playing` 的空闲位，全忙顶掉 `_chi[0]`——连吃一串鱼时后一口必须响；同一帧多处触发不打架 |
| `AudioStreamWAV` + `preload` 音效表 | 11 条音效进 `YIN_XIAO_BIAO` 字典（`&"chi"` → 流），未知名 `push_warning` 不炸——热更数据音效名写错只丢一声，不崩游戏 |
| `volume_db` | Godot 的音量单位是分贝不是 0~1：音效默认 0dB，BGM 常驻 -10dB（氛围垫底不抢反馈）；`fang(名, -4.0)` 可单条压低（NPC 咬玩家比玩家咬人小声） |
| `finished` 信号手动续播 | `AudioStreamWAV` 默认不循环；`_bgm.finished.connect(func(): _bgm.play())`——BGM 的 WAV 首尾做交叉淡化，续播点无缝 |
| Autoload 的编译期引用陷阱 | `--script` 纯逻辑测试**不注册 Autoload 全局名**：`yin_xiang.gd` 里写 `ZhangBen.xxx` 是编译期引用，会让第 2~7 步全部编译失败；改 `get_node_or_null("/root/ZhangBen")` 运行时查找，编译期零依赖（场景模式 Autoload 全就位，照常连信号） |
| 音效归口三原则 | 吞吃音在动作帧发（`_chi_diao` 末尾，等消化到账再响就晚了）；升级音由 YinXiang **监听账本信号**（触发方不用关心声音）；结算音只在结算页分支里发 |
| 退出时的 `resources still in use` | Godot 的资源检查**早于场景树析构**：`AudioStreamPlayer` 被 `stop()` 后还要几帧才释放内部 `AudioStreamPlayback` 引用，掐着声退出必泄漏（ERROR 级） |
| 测试收尾的正确姿势 | 停声 → 等 ≥4 帧 → quit。死亡用例切场景会 free 本测试节点，`await` 挂起的协程不再恢复——收尾必须走 `SceneTree.process_frame` 信号 + **纯闭包**（不挂节点，切场景拆不掉） |
| 负载差异的坑 | 收尾按帧数不按墙钟：`SceneTreeTimer(0.2)` 在系统忙时只有几帧就跳，释放没跑完就退出——「单独跑全绿、门禁里翻车」的经典根源 |
| lambda 值捕获 | GDScript 闭包捕获的是**定义时的值**：`var f: Callable; f = func(): f.xxx` 里 f 是 null（右边先求值）；自引用要装进数组 `lian[0]` 再在体内取 |
| 闭包引用环要手动断 | 闭包捕获数组、数组又装着闭包 → 环；quit 前 `lian.clear()` 断掉，否则脚本资源挂到退出报 still in use |
| Area 信号靠物理时序 | `area_entered` 要等物理步进后才发：负载高时「把鱼放到玩家身上等吞」的用例会偶发吞不到；测业务链就直调业务函数（`_chi_diao`），别赌信号时机 |
| 嘴圈边缘站位 flaky | 80px 站靶鱼恰在嘴圈（55px×scale + NPC 形状）边缘：物理时序一晃就被误吞（`si_le=true`）；测放电先 `zui_qu.monitoring = false` 关吞吃，用完还原 |

### 概念小结

| 概念 | 一句话 |
|---|---|
| 档位是数据不是代码 | 升档 = 换 `dang_biao` 里的一行数值：`match` 分支一条不加，强度照样上台阶 |
| 只写差异项 | 档位表是"覆写"不是"完整表"：缺省回退基础字段，表越小越不容易两边不一致 |
| 满层 ≠ 多一层，是换一档 | 被动满层覆写主值、附加键另读：线性曲线和"质变"两套语义不打架 |
| 满档静默 + 抽牌排除 | 账本对超额选择不报错不重置；三选一保证满档卡根本不会出现——双保险各管一头 |
| 感知只有一个出口 | 淤泥雾、隐匿气息都只在 `dang_qian_gan_zhi` 处乘系数：以后加"看不见"类能力零改动 |
| 定身复用反应延迟 | 漩涡/声呐不写新状态机，往 `_fan_ying_ji_shi` 写时长即可；首领免疫是同一条通道的天然副产品 |
| 咬击联动只挂一个点 | 撕裂齿/毒腺都挂在 `_yao_ji_lian_dong`：以后加"咬击吸血"还是这一个函数 |

### 概念小结

| 概念 | 一句话 |
|---|---|
| 账本是状态，存档是快照 | 序列化只挑可序列化字段，位置/AI 不进档——继续游戏 = 快照数值 + 重新生成的世界 |
| 生命周期收口在信号 | 开局清、结局清、载入写：三条规则挂在"开始按钮 / ju_jie_shu 回调 / 返回按钮"三个必然事件上，没有第四处要记 |
| 复用面板靠 @export | 一份 SheZhi.tscn 两种身份：场景里改一个布尔，"返回主界面并保存"就消失 |
| 暂停归属要记账 | 谁设的暂停谁解——面板记 `_ben_mian_zan_ting`，才不会把三选一弹窗的冻结误开 |
| 测试与真实存档隔离 | 路径是 var 不是 const：测试换临时路径 + 进程号，胜负回调删的永远是临时文件 |
