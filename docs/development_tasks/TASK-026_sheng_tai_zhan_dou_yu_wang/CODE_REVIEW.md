### 雷达红点（`xiao_di_tu.gd`）

- `ji_lu_ke_hua()` 是纯函数，输入语义按 `typeof` 分三类：
  - `typeof(node) == TYPE_NIL` → 未加载房，照画（保留九房雷达视野）；
  - `TYPE_OBJECT` 但 `not is_instance_valid(node)` → 已释放但记录未删的鱼，不画；
  - 有效节点且未死 → 画；`si_le == true` → 不画。
- 当前房同步会删死鱼记录，未加载房不能同步，因此无效节点兜底是必要的，不是冗余判断。
- `qing_chu_qi_ta_fang_ji_lu()` 只在停刷清房路径调用，不会误删当前房记录。
- 测试无需拦截绘制，纯函数直接断言；这是可测试性最好的做法。

### 雷达残留补丁审查（2026-11-15 用户反馈）

- 关键事实：Godot 4 中已 `queue_free` 的对象存进 `Dictionary` 后，`obj == null` 为真，但 `typeof(obj)` 仍是 `TYPE_OBJECT`；只用 `== null` 判断会把“已释放对象”和“故意置空的未加载记录”混为一谈。
- `_tong_bu_dang_qian_fang_jian()` 与 `_bao_cun_dang_qian_fang_jian()` 已改为先看 `TYPE_NIL`，再走 `is_instance_valid` / `si_le`；死记录一律 `remove_at`，不会被 `node=null` 洗成永久虚拟鱼。
- `yu_wang_shu()` 同步排除已释放节点，避免名额统计在死鱼记录上多算。
- 新增断言直接构造“已释放对象”并断言 `typeof` 前提，防止以后有人把判断改回 `== null` 而测试仍绿。
