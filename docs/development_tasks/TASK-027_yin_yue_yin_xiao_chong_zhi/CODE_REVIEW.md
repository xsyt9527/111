## 一、逐项审查

### 音效生成器（`tools/yinyue/shengcheng_yin_xiao.py`）

- `JOBS` 19 条与 `YIN_XIAO_BIAO` 19 键一一对应：12 条既有 `yin_xiao_*` 重写，7 条旧键新增 `yin_xiao_an_niu/chi/tan_chuang/fang_neng_li/shi_kong/sheng_li/shi_bai`，没有漏项，也没有多生成未接线的文件。
- `triple()` 把第二/第三振荡器的 `finel/finer` 统一由 `fine1/fine2` 成对写入；这是对 LMMS 1.2.2 单边失谐行为的针对性修复，所有调用点的音色一致性由此保证。
- `track()` 新增 `pattern_len`，默认 192 ticks 保持旧行为；只有 `sheng_li` 两条轨显式传 240 ticks。改动面收敛，不影响其余 18 条。
- `validate()` 的阈值合理：
  - 时长 ±0.002s 足以抓住裁剪错位，又不会因 LMMS 帧对齐误报；
  - 峰值 -3.0 ~ -1.0 dBFS 覆盖归一化目标 -1.5 附近；
  - 循环类只查首尾样本差与端点电平，不使用文件内部相邻跳变作阈值（F11 是方波，陡边本身就有正常满幅跳变），判断口径正确。
- 专项探针保留在 `main()`，且失败即 `SystemExit`：F5 静默段、F10 800Hz、F11 四段警报、F1 低频 thump，都是“听感问题可被数值提前抓住”的代表项。
- 后处理顺序（下混→定长→去直流→淡入淡出→归一化→循环折回）正确；先归一化后折回可能让循环端点略超峰值，但折回的是尾音且随后仍满足 -1.50 dBFS 实测，风险可接受。

### BGM 生成器（`tools/yinyue/shengcheng_yinyue.py`）

- `inst_triple` 的 `finel1/finer1` 成对写入是本次“怪怪的”根因修复；docstring 记录清楚，后续新增曲目不会再踩同一个坑。
- `qu_shen_hai`：只动失谐、低通与钟琴力度/音量，三层结构（和声垫、低音持续、稀疏钟声）未变；`fine1=0` 让长音垫不再有单声道拍频。
- `qu_tan_suo`：删除沙锤轨、去掉闭镲加花、压低军鼓与闭镲，方向是“减少高频堆叠”；贝斯/琶音/旋律的低通同步下调，整体高频密度下降但节奏骨架保留。
- `qu_jue_zhan` 重写符合用户反馈：
  - 删除十六分锯齿推进贝斯、锯齿+方波主旋律、每小节六次切分铜管、拍手/吊镲/十六分闭镲、`snare_harsh` 与 C→C# 半音；
  - 保留低频持续（正弦根音+五度，2 小节换 Em/C/G/D）、暖垫、干净四拍、克制铜管四层；
  - 16~19 小节的鼓组减拍与 20/22 小节收尾上行给曲式留了呼吸，不是平铺 24 小节；
  - 140 BPM / 24 小节 / 41.14 秒未变，循环契约不受影响。
- `validate_bgm()` 覆盖格式、时长 ±0.05s、峰值 ±1dB、首尾 10ms 电平与接缝；`render()` 末尾强制调用，失败即中止，避免坏文件静默落盘。
- `dbfs()` 提为模块级函数，`validate` 与 `validate_bgm` 共用，无重复实现。
- `render()` 渲染后 `os.remove(raw)`，`main()` 结束 `shutil.rmtree(RENDER_DIR)`，临时中间文件不残留。
